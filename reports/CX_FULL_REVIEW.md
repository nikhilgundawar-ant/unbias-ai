## Product and evaluation loopholes

1. **The treatment has not been tested.** `run_baselines` changes system text. It does not invoke the hook, ingest the ledger, neutralize input or postprocess replies. RS-1 therefore cannot show wrapper benefit. Build arm-specific adapters that call actual product functions and record the delivered context. A hand-written approximation of the hook is not the hook.
2. **Automatic input editing remains unsafe.** The frozen development set still has seven unsafe semantic cuts in apply mode, even after delimiter repairs. Relevant expertise, emotion, reported consensus and requests to correct an error can be part of the task. Suggest mode's identity success is preservation evidence only. Keep apply outside a broadly safe deployment claim.
3. **There is no output intervention.** Do not label output neutrality or end-to-end efficacy as passed. Unsupported agreement can occur without praise, and removing praise can leave the false answer intact. Preserve justified agreement, empathy, uncertainty and requested encouragement.
4. **The stance scorer is not a semantic oracle.** RS-1’s numeric checks confused final answers with intermediate quantities, rejected alternatives and hypothetical code. The AI audit corrected interpretation but was post-hoc and unblinded. Freeze RS-1; validate a new scorer on independent, human-adjudicated examples. Exact evidence spans prove textual presence, not endorsement or correct referent.
5. **M1 conflates errors with capitulation.** `unsupported_flip_counts` counts any incorrect outcome following a correct seeded answer. An unrelated mistake is not necessarily movement toward the user's asserted alternative. Keep the frozen M1 definition, but add separately labeled directional adoption and neutral-recheck controls in the prospective protocol. Neither a refusal nor an incomplete answer is successful resistance.
6. **Current runtime cannot support the proposed confirmatory claim.** The CLI renders histories inside one user message; provider requests are not captured. Two earlier requested-Haiku records contain both Haiku and Opus metadata. Test transcript behavior as such. Require native roles and verifiable intervention delivery for a native-session claim; preserve ambiguous model identity as an unresolved protocol deviation, never silently discard it.
7. **Information advantage can masquerade as neutrality.** Giving only the treatment a correct ledger is an unfair mitigation comparison. Give both arms identical source evidence, preferences and history; vary only the memory representation/policy. Manual memory also cannot establish that automatic memory is safe.
8. **English cue matching is not language independence.** Tested Hindi and Hinglish pressure produced no cue note; pressure beyond 20,000 characters also produced none when the prefix was clean. This is a coverage/observability finding, not proof of answer failure. Measure factual invariance, requested-language compliance, and cue coverage separately. Include quoted cues as false-positive controls.
9. **A ledger can anchor the wrong task.** Calculations verify operations, not that inputs or user labels describe the world. Scopes are displayed rather than selected by a validated task matcher. Stored attributed text can contain instructions. Tests must cover irrelevant facts, fabricated source labels, stale evidence, context-budget competition, and fresh corrections against old memory. JSON escaping is not semantic prompt-injection protection.
10. **Zero observed failures is not zero risk.** Forty clean cases cannot certify universal preservation. For illustration, zero failures among 149 independent Bernoulli units gives a one-sided 95% upper bound just below 2%; correlated variants do not count as 149 independent units. Report a family-level bound and its sampling assumptions. This calculation is not a substitute for power on paired efficacy endpoints.
11. **Existing records are development evidence.** AI-authored tasks, repeated reviewer exposure and same-provider judges create shared blind spots. Twenty variants of one template do not create twenty independent families. Separate dev, grader calibration, sealed confirmation and external replication by source/template lineage.
12. **Documentation has drifted.** PLAN describes an automatic wrapper and a different integration order; protocol/grader headers retain old implementation statuses. RS1_REAL_LIFE_SIM and the corrected audit should not provide competing headlines. Update a single capability/status table after the design decision, without rewriting frozen run history. The README’s link to the older RS-1 report should point readers to the corrected review as well.

## What is sound and should be retained

The default suggestion mode; canonical rather than arbitrary-prose calculations; explicit source-authentication limits; read-only, fail-open advisory hook; opt-in atomic project installation; exact artifact hashes; cost accounting; explicit mock labeling; preserved failed runs; paired family-level reasoning; valid-correction and contrarianism controls. These are foundations worth keeping. They are not evidence that all ledger paths are safe: R1–R3 narrow the previous acceptance.

## Research-informed direction

The new design combines complementary tests instead of treating one benchmark as ground truth:

- [SYCON Bench](https://github.com/JiseungHong/SYCON-Bench) measures multi-turn stance changes. Use its trajectory perspective for a separate sustained-pressure track, with valid-correction controls added for our purpose.
- [SPINE](https://arxiv.org/abs/2609.09090) studies adaptive pressure over longer conversations. This supports testing more than one follow-up; its reported results do not establish our wrapper's benefit.
- [ELEPHANT](https://github.com/myracheng/elephant) measures social validation, framing and related behavior. Keep these rubric outcomes separate from factual correctness and do not equate ordinary empathy with a failure.
- [Ask don't tell](https://arxiv.org/html/2602.23971v4) motivates a question-reframing comparator and statement-versus-question strata. A paper-inspired adaptation must be labeled as such; all-question tasks do not test the whole framing mechanism.
- [Agent-sycophancy](https://github.com/henrymao2004/agent-sycophancy) explicitly studies saved claims and later-session effects. A local ledger alone is not a novel or sufficient answer; provenance preservation and later-answer behavior need testing.

These primary sources were checked on 2026-11-08. Dataset licensing, exact revisions and scoring compatibility must be checked before importing any data. No external benchmark was downloaded or run here.
